# AI-тренер

Реализация: `portal/routers/ai.py` (668 строк). Три независимые
функции, каждая — отдельный `subprocess.Popen` вызова Claude Code CLI.
В коде нет ни одного прямого HTTP-вызова к `api.anthropic.com` и нет
Python-SDK `anthropic`.

## Кто отвечает — не Anthropic API, а Claude Code CLI

Все три функции запускают один и тот же бинарь одинаковым способом:

```python
subprocess.Popen(
    [config.CLAUDE_CLI_PATH, "-p", prompt, "--output-format", "stream-json", "--verbose"],
    stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True, bufsize=1,
)
```

Ответ читается построчно из `stdout` как поток JSON-событий; текст
собирается из блоков `event["message"]["content"]` с `type == "text"` у
событий `type == "assistant"`; событие `type == "result"` (или конец
потока) завершает чтение.

Практические следствия:

- **Модель и лимиты не выбираются кодом портала.** Параметра `model=...`
  в вызове нет — используется то, что настроено в самой CLI-подписке
  (`ANTHROPIC_API_KEY` либо файл авторизации в `HOME/.claude`, см.
  `.env.production.example`). Какая модель отвечает сейчас — требует
  проверки на самом деплое.
- **Нет системного промпта отдельно от пользовательского** — весь текст
  (роль тренера, контекст, данные, формат ответа) собирается в одну
  строку и передаётся единственным аргументом `-p`.
- **Нет многоходовой сессии** — каждый запрос независимый, `--resume`/
  `--continue` не используются. История прошлых пробежек и записей о
  здоровье не хранится в диалоге с моделью, а каждый раз заново
  вклеивается текстом в промпт.
- **Отказоустойчивость разная у трёх функций** — см. ниже.

## 1. Разбор конкретной пробежки

`POST /api/ai/analyze` → `GET /api/ai/analyze/stream` (SSE).

**Вход** (`build_prompt`, `portal/routers/ai.py:191`, шаблон —
`settings.activity_prompt_template`):

- метрики выбранной пробежки: дата, дистанция, пульс, темп, каденс,
  длина шага, нагрузка, восстановление, доли времени по пульсовым
  зонам;
- последние 10 пробежек (дата, дистанция, пульс, темп, нагрузка);
- последние 3 записи журнала состояния;
- текущая дата.

**Выход:** связный текст на русском, 3–5 предложений (формат задаёт сам
текст промпта, JSON не требуется). Стримится в браузер по
`text/event-stream` чанками по мере генерации, финальный текст
сохраняется в `ai_analysis` (кэш без TTL — до явного «Пересчитать
анализ» с `force_refresh=true`).

**Отказоустойчивость:** минимальная — при ошибке (`FileNotFoundError`
для CLI или любое другое исключение) в поток уходит одно SSE-событие
`{"error": ...}`, ничего не сохраняется, повторной попытки нет.

## 2. «Ответ на сегодня»

`GET /api/ai/recommendation`, обновление — `POST
/api/ai/recommendation/refresh` (вызывается вручную с дашборда или
планировщиком после успешной синхронизации).

**Вход** (`build_daily_prompt`, `portal/routers/ai.py:282`, шаблон —
`settings.daily_prompt_template`): последняя пробежка целиком, часы с
её момента, последние 7 пробежек, последние 3 записи журнала
состояния, **сохранённый текстовый разбор последней пробежки** (из
`ai_analysis`, если он уже есть — единственное место, где выход одной
AI-функции становится входом другой), текущая дата.

**Выход:** строго JSON `{"status": "run" | "run_easy" | "rest",
"message": "..."}`. Критерии выбора статуса заданы прямо текстом в
дефолтном промпте (`portal/db.py:129`):

- `rest` — не истёк `recover_time` последней пробежки, или пульс был
  выше 185, или активная запись о здоровье/сохранённый разбор говорит о
  боли/травме/необходимости паузы;
- `run_easy` — пульс 170–185, или нагрузка выше 200, или
  `recover_time` почти истёк;
- `run` — всё в норме.

Парсинг ответа (`_parse_claude_json`) снимает возможную обёртку
```` ```json ... ``` ````, дальше — обычный `json.loads`; невалидный JSON
считается ошибкой.

**Отказоустойчивость:** результат (успех или ошибка) всегда сохраняется
— успешный в `daily_recommendation` (лог, новая строка на каждый
вызов), ошибка — в служебную настройку
`daily_recommendation_error` как JSON `{"status": "error",
"error_code": ..., "message": ..., "action_label": ..., "action_url":
"/claude-auth"}`. `GET /api/ai/recommendation` сначала проверяет эту
ошибку и, если она есть, отдаёт её вместо последней (устаревшей)
успешной рекомендации — так на дашборде не показывается тихо
протухшая рекомендация. `_recommendation_error_response` различает два
случая по тексту исключения: истёкшая OAuth-сессия CLI (маркеры вроде
`"OAuth session expired"`, `"Not logged in"`) даёт
`error_code: "claude_auth_expired"` с прямой ссылкой на `/claude-auth`;
всё остальное — общий `error_code: "claude_unavailable"`.

## 3. Предложение цели на месяц

`GET /api/goals/monthly/suggest`.

**Вход** (`generate_goal_suggestion`, `portal/routers/ai.py:476`):
статистика по последним 4 месяцам (км + число пробежек) и последние
10 пробежек. Промпт **захардкожен прямо в этой функции** (не в
`settings`, в отличие от двух остальных, и поэтому не редактируется
через `/settings`), с фиксированным ограничением «нельзя увеличивать
месячную нагрузку больше чем на 20% относительно лучшего предыдущего
месяца».

**Выход:** JSON `{"km_goal", "runs_goal", "message", "conservative":
{...}, "ambitious": {...}}`, нормализуется и обрезается в разумные
границы (`_normalize_goal_suggestion`: 1–1000 км, 1–31 пробежка).

**Отказоустойчивость — заметно выше, чем у двух других функций.** При
любой ошибке (CLI недоступен, невалидный JSON, таймаут) вызывается
`_monthly_goal_fallback` (`portal/routers/ai.py:407`) — чисто
арифметическая эвристика без обращения к AI: цель берётся как лучший
результат за последние 3 месяца, умноженный на 1.15 (но не более чем
+10 км), консервативный/амбициозный варианты — ±15% от неё. Ответ в
этом случае помечается `"reasoning": "fallback_after_error"` и к
тексту добавляется пояснение «AI-анализ сейчас недоступен».

## Общее для всех трёх

- Промпты для функций 1 и 2 хранятся в `settings` как обычный текст с
  плейсхолдерами `{current_date}`, `{last_date}`, `{recent_lines}`,
  `{health_lines}` и т.д. (полный список — на странице `/settings`) и
  редактируются через UI без деплоя; рендерятся через
  `str.format_map` с «безопасным» словарём (`_SafeDict`), который
  оставляет неизвестный плейсхолдер как есть вместо `KeyError`.
- Дефолтные (сидируемые) значения этих промптов и захардкоженный
  промпт цели на месяц содержат реальный личный контекст владельца
  портала (травма, конкретная модель кроссовок) — см.
  предупреждение о приватности в корневом README/итоговом отчёте.
- Обновление OAuth-сессии Claude CLI, на которой держатся все три
  функции — через страницу `/claude-auth`
  (`portal/routers/claude_auth.py`), см.
  [`docs/workflows.md`](./workflows.md#обновление-авторизации-claude-cli).
